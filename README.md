## 1000×1000 1D 배열 추가 실험

### 실험 목적

보너스 1에서 학습한 2D 배열의 1D 평탄화(Flattening) 방식을 오늘 실습한 행 단위 처리에도 적용해 결과와 실행 시간을 비교합니다.

### 비교 방식

1. **2D 전체 배열**: 2차원 리스트를 만든 뒤 행·열 인덱스로 MAC 계산
2. **1D 전체 배열**: 입력과 필터를 길이 `N × N`의 1차원 리스트로 만들고 하나의 인덱스로 MAC 계산
3. **2D 행 단위 처리**: 입력을 한 행씩 생성하고 2D 필터의 행·열 인덱스로 누적
4. **1D 행 단위 처리**: 입력을 한 행씩 생성하고 평탄화된 필터를 `row_index * N + col` 인덱스로 접근해 누적

### 실행 방법

```bash
python large_scale_1d_test.py
```

각 방식은 7회 측정하며, 실행 시간은 중앙값(median)을 표시합니다.

### 검증 결과

1000×1000 Cross/X 패턴에서 네 가지 방식 모두 같은 점수를 반환했습니다.

| 입력 패턴 | Cross 필터 점수 | X 필터 점수 |
|---|---:|---:|
| Cross | 3,996 | 4 |
| X | 4 | 2,000 |

Cross 패턴은 중앙 두 행과 중앙 두 열을 1로 설정합니다. 따라서 Cross 필터와의 겹치는 위치 수는 `2,000 + 2,000 - 4 = 3,996`입니다. X 패턴은 두 대각선에 해당하는 총 2,000개 위치가 1입니다. Cross와 X가 겹치는 위치는 4개입니다.

### 이번 실행 환경에서 측정한 시간

아래는 각 방식의 7회 측정 중앙값입니다. 단위는 초(second)입니다.

| 입력 | 2D 전체 | 1D 전체 | 2D 행 단위 | 1D 행 단위 |
|---|---:|---:|---:|---:|
| Cross | 0.114473 | 0.082979 | 0.274711 | 0.277260 |
| X | 0.125704 | 0.090554 | 0.239732 | 0.241424 |

※ 실행 환경과 부하에 따라 시간은 달라질 수 있습니다. 전체 배열 방식은 배열 생성이 끝난 뒤 MAC 계산만 측정합니다. 행 단위 방식은 각 행을 생성하는 시간도 측정에 포함합니다. 따라서 전체 배열과 행 단위 방식의 시간은 측정 범위가 완전히 같지 않습니다. 행 단위 방식끼리의 비교는 같은 행 생성 작업을 포함합니다.

### 해석

- 이번 측정에서 1D 전체 배열 방식은 2D 전체 배열 방식보다 Cross 입력에서 약 27.5%, X 입력에서 약 28.0% 빠르게 측정됐습니다.
- 1D 행 단위 방식은 2D 행 단위 방식보다 Cross 입력에서 약 0.9%, X 입력에서 약 0.7% 느리게 측정됐습니다.
- 따라서 1D 배열을 행 단위 방식에 적용했다고 해서 실행 시간이 반드시 줄어드는 것은 아닙니다. 이번 측정에서 행 단위 방식 간 시간 차이는 1% 이내였습니다.
- 행 단위 방식은 전체 입력 배열을 보관하지 않고 한 행씩 처리할 수 있다는 점에서 입력 데이터의 임시 저장 공간을 줄이는 데 의미가 있습니다.
- 네 가지 방식의 계산 결과가 모두 일치하는지 확인하는 것이 이번 실험의 핵심 검증입니다.

### 핵심 용어

- **Flattening(평탄화)**: 2차원 배열의 행과 열 구조를 1차원 배열로 펼치는 것
- **Index(인덱스)**: 배열 안의 데이터 위치를 나타내는 번호
- **Streaming(스트리밍 처리)**: 전체 데이터를 한 번에 보관하지 않고 작은 단위로 순차 처리하는 방식
- **MAC(Multiply-Accumulate)**: 같은 위치의 값을 곱한 뒤 누적해서 더하는 연산
- **Median(중앙값)**: 측정값을 크기순으로 정렬했을 때 가운데에 위치하는 값
